# AI Platform Specification: ELO Security Architecture & Tool Gatekeeper

## Overview
The **ELO Subsystem** serves as the intelligent operational assistant and autonomous automation agent across the infrastructure platform. Because ELO interacts directly with hypervisors, network appliances, and host configurations, a deterministic security framework is required to prevent unauthorized, catastrophic, or hallucinatory actions.

## Security Permission Tiers (L0 – L3)

| Tier | Name | Allowed Capabilities | Auth Requirement | Human Approval | Rollback Required |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **L0** | Read-Only Telemetry | Query Prometheus metrics, scrape Uptime Kuma statuses, inspect container running states, view DNS blocklists. | Standard Agent Token | **None (Autonomous)** | No |
| **L1** | Idempotent Mutation | Generate configuration diffs, create draft documentation, format IaC files, run static security linting. | Agent Service Account | **None (Autonomous)** | Git Revert |
| **L2** | Operational Mutation | Restart non-critical containers, apply vetted firewall blocklist updates, rotate temporary API keys. | Elevated Agent Token | **Operator Notification** (Async) | Snapshot / Rollback |
| **L3** | Privileged / Destructive | Stop core firewall (VM 200), purge database volumes, delete VM snapshots, modify hypervisor root password, repartition disks. | Dual-Factor Root Operator | **Strict Human Approval Required** (Interactive) | Mandatory Pre-Snapshot |

## Tool Execution Gatekeeper Pipeline

Every tool call generated by an LLM model must transit the **Gatekeeper Pipeline**:

1. **Intent Extraction**: The tool call payload is validated against strict JSON Schema definitions. Unrecognized parameters or injection attempts are dropped.
2. **Policy Evaluation**: The target action is mapped to its corresponding risk tier (L0 to L3).
3. **Permission Check**: The system validates that the initiating session possesses the necessary authorization tokens.
4. **Interactive Approval Gate**:
   - For **L3 actions**: Execution is suspended. An out-of-band notification (ntfy / Telegram push) is dispatched to the platform operator displaying the exact command, target host, and justification.
   - Execution resumes **only** upon cryptographic approval from the operator.
5. **Pre-Flight Snapshot**: If the action alters persistent state, an automated snapshot of the target container or VM is generated.
6. **Execution via Proxied API**: The Gatekeeper executes the action using least-privilege API tokens.
7. **Immutable Audit Logging**: The full trace (timestamp, model ID, prompt token hash, exact tool parameters, operator approver ID, and exit code) is forwarded to Wazuh SIEM via syslog.
